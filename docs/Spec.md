# Spec.md — 提问式学习智能体（AskToNote）

> 状态：已定稿（v1 demo 需求冻结）
> 规范驱动开发（SDD）第一步——产品需求规格。

---

## 1. 背景与问题

学习一个陌生领域时，最难受的不是"没有答案"，而是**连锁陌生**：从"什么是 Docker"开始，AI 解释里又冒出"容器、镜像、虚拟化、Hypervisor……"。用户被迫在一堆陌生概念里来回跳，既记不住、也形不成体系。

现有 AI 对话工具能回答问题，但有两个断层：

1. **陌生点靠用户自己发现**——用户要自己意识到"我不懂这个词"，再自己组织提问，对初学者门槛高。
2. **答案没有沉淀**——每次问答孤立，学完没留下结构化笔记，知识无法积累。

## 2. 产品定位

一个帮助用户**从一个问题开始，顺藤摸瓜构建完整知识网络**的学习助手。

核心主张：**每一个陌生点，都是一个可以延伸的问题；每一次标注，都是笔记的扩写。** 用户最终既搞懂一串知识，也留下一份结构化笔记。

## 3. 目标与非目标

### 3.1 目标（v1 demo，长测验证）

- 用户提初始问题 → AI 优化问题并生成回答，回答即**笔记内容**；每次提问在主题文件里形成一段 **Q/A 区块**（一主题一文件）。
- 用户对回答/笔记中的陌生点**手动划词标注**（可多个）。
- AI 基于标注**猜测用户想问什么**，生成候选问题供用户确认/修改。
- 每个标注由用户选择了解深度：**简单了解 / 深入了解**，随后**原地扩写笔记**。
- 维护**用户知识记忆**（概念掌握度 + 背景），逐步"用越久越好用"。
- 循环可反复进行，直到用户搞懂该领域的知识链。

### 3.2 非目标（明确排除，v2 再议）

- **知识网络可视化**（图谱/思维导图）——内链已写进 MD，画图是展示层，后做。
- 多用户登录 / 权限隔离。
- 向量检索 / 大规模记忆检索。
- 笔记全文自动整理/去重（v1 笔记是原地增补，不做合并）。

## 4. 核心用户流程

```
用户提问（初始问题；后续再提问也走同一条路）
    ↓
问题优化智能体（模式A）：优化问题 + 命名主题（slug/title） → 用户确认/修改
    · slug = 当前主题 → 以 Q/A 区块追加到该主题笔记
    · 关联弱（并行关系）→ 新 slug，经用户确认后新建主题文件
    ↓
解答笔记智能体（模式①作答）：流式纯 Markdown 回答 → 以 `## 问题` + 回答正文 的 Q/A 区块追加/存为笔记
    ↓
用户划词标注陌生点（可多个；流式结束、MD 渲染完成后才可标注）
    ↓
问题优化智能体（模式B）：生成候选问题列表（含每个标注对应的规范概念）→ 用户确认/修改
    ↓
【一次一个】取一个标注：用户选「简单了解 / 深入了解」
    ↓
解答笔记智能体（模式②标注扩写）：
    简单了解 → 在插入点插入括号简释
    深入了解 → 插入点括号简释 + 紧跟该段落新增小标题章节
    ↓
记忆：该标注概念置 pending（不在库 = 10 / 已在库 分数不变）
    ↓
用户读完点「已理解」→ 该概念 pending 清除、分数 +10；不想现在懂可点「跳过」→ 记忆不变、直接进入下一条
    ↓
（回到"取一个标注"，可继续标注新出现的陌生点）→ 产出：搞懂知识链 + 一份持续扩写的 MD 笔记
```

## 5. 架构

### 5.1 组成

| 组件 | 职责 | 与记忆的关系 |
|---|---|---|
| **问题优化智能体** | 模式A：优化单个初始问题 + 命名主题（slug/title）；模式B：把标注转成候选问题列表（含规范概念） | 读记忆 → 决定怎么问 |
| **解答笔记智能体** | 模式①作答：流式纯 Markdown 回答（=笔记内容）；模式②标注扩写：插入点插入括号解释 / 新增小标题 | 读记忆（**已掌握** / **尚不熟悉**两类）→ 决定讲解深度/类比 |
| **背景推断** | 独立调用，**每次会话开始做一次**：读用户概念记忆 + 已有主题（仅标题）推断背景，用户可视可改 | 读记忆/主题 → 写 `user_profile.background` |
| **用户知识记忆** | 概念掌握度表 + 用户背景（**背景由记忆自动推断**） | 随「标注 / 学懂确认」更新；**背景**可用户手改并锁定（概念分数只读） |

> 记忆**不**做 LLM 概念自动提取：概念名由**问题优化智能体（模式B）**在标注时给出，掌握度只由**用户标注**与**「已理解」确认**两个显式行为驱动。

### 5.2 核心数据关系（避免冗余）

- **笔记（MD 文件）= 知识「内容」**——一串 **Q/A 区块**（`## 问题` + 回答），人读的产物，`[[内链]]` 天然形成知识网络。
- **用户知识记忆 = 掌握「状态」**——只存"概念名 + 掌握度 + 背景"，机器读的决策依据，不复制知识正文。

```
笔记内容 + 用户标注 / 「已理解」确认
        │
        ▼
用户知识记忆（掌握度状态）
        │ 读
   ┌────┴────┐
解答笔记智能体  问题优化智能体
```

- 记忆**来源** = **用户显式行为**：标注（= 此处不懂）与「已理解」确认（= 已学会）。**不**依据"未标注"推断用户已懂。
- **背景由概念记忆推断**（用户在哪些领域掌握/正在学习大量概念 → "熟悉 Java 后端"），并可由用户手动纠正。
- AI **输入** = 笔记（内容）+ 用户知识记忆（状态）。
- **记忆喂给 AI 时按分数分两类**：`score ≥ 50` → 【已掌握概念】；`score < 50` → 【尚不熟悉的概念】（多为用户标注过、还没学会的词，**需重点讲清、不得当作已掌握**）。背景推断同用这两类：前者推"熟悉 X"，后者推"正在学 X"。

## 6. 功能需求

### 6.1 提问与回答
- FR-1：用户输入初始问题（自然语言）。
- FR-2：系统先经问题优化智能体（模式A）优化问题，并**命名主题**（返回建议 `slug`/`title`）。**优化后的问题**展示给用户确认/修改后发出；**`slug`/`title` 由 AI 生成、用户不可修改**（后端校验 `slug` 合法并去重；**非法则回退为并入当前主题**）。
- FR-3：解答笔记智能体（模式①）生成回答，以**流式（SSE）纯 Markdown** 逐步返回并实时渲染——**没有额外结构化包裹、无分隔符协议**。
- FR-3b：回答内容**即为笔记内容**。若 `slug` 属当前主题 → 以 **Q/A 区块**（`## {确认后的问题}` + 回答正文）**追加**到 `data/notes/{slug}.md` 末尾；若关联弱（并行关系）→ 由模式A 命名新 `slug`，经用户确认后**新建**主题文件。
- FR-3c：**后续提问也先过模式A**（判断主题归属），因此每个主题文件始终能确定 `slug`，不依赖前端猜测。

### 6.2 标注与问题确认
- FR-4：用户可在**笔记文本**中**手动划词标注**多个陌生点（不做 AI 预标注）；标注仅在**流式结束、Markdown 渲染完成后**启用（流式期间禁用，避免文字位移）。
- FR-5：每个标注片段作为输入传给问题优化智能体（模式B），生成**候选问题列表**（**一个片段对应一个问题，不合并**），每项含：猜测的问题 `text`、对应的**规范概念名** `concept`、**标注对象类型** `kind`（`concept`=概念 / `statement`=说法）、理由 `reason`。
- FR-6：用户对列表可确认、删减、编辑后提交。提交后系统**一次只处理一个标注**（含深度选择 → 扩写 → 用户确认），处理完一条再进入下一条。

### 6.3 笔记扩写
- FR-7：每个标注由用户**单独**选择了解深度——**简单了解 / 深入了解**。
- FR-8：**简单了解**——在**插入点**插入一段括号简释（不新增标题）。定位（**优先词后、兜底段末**）：
  - 按空行切段，先在**源码**里 `find(anchor)`（grep 式）；命中**正文段** → 插到该 anchor **之后**（词后）；
  - 源码搜不到（anchor 跨行内标记，如 `**容器**和**镜像**`）→ 对每段**单独脱标记**后 `find(anchor)`，命中 → 插到该**段落源码末尾**；
  - 仅命中**标题行**时改用该标题下**首个正文段**；都找不到 → 提示用户重新选择。
- FR-9：**深入了解**——在插入点插入括号简释 **+ 紧跟该段落之后新增一个小标题章节**（标题固定用 `####`，如 `#### 镜像`）并展开讲解。
- FR-9b：扩写返回后用户阅读；点「已理解」→ 该标注对应概念的记忆更新（`pending` 清除、`score += 10`，见 §7），系统随即进入**下一个**标注；也可点「跳过」→ **记忆不变**（标注时已置的 `pending` 保持）、**不回滚**已写入的扩写内容，直接进入**下一个**标注（跳过 ≠ 撤销，撤销留 v2）。用户也可**在扩写内容上继续划词**——新标注立即过模式B 拿候选问题与深度，并**插到待处理队列最前、优先处理**（**递归下钻**，后序：先弄懂叶子再回上一层）。
- FR-10：**标注是"说法"而非概念**时（如"低耦合的代码很优秀"）——括号解释该**说法**本身；同时把该说法**由模式B 提炼出的那个概念**记入记忆（不在库则新建 10 分），与概念标注走同一规则。

### 6.4 循环
- FR-11：扩写后可继续标注（含**在扩写内容上中途划词、插队优先处理**），循环直到用户不再标注新陌生点、待处理队列清空。

### 6.5 笔记
- FR-12：一个学习主题一个 MD 文件，文件为 `data/notes/{slug}.md`（路径相对运行目录 `backend/`，即 `backend/data/notes/{slug}.md`）。文件以 `# {title}` 开头，内容按**问答分块**组织：每次提问写一个 `## {问题}` 标题，下面是该问题的回答正文（问题与答案组织在一起）；标注扩写在该回答**内部**原地插入，不新开 Q/A 区块。
- FR-13：用户可实时查看笔记内容（前端笔记预览区）；**页面加载时默认打开最近更新的一篇**（"继续上次学习"），**无主题时为空态、引导提问**。
- FR-14：**主题边界判定**——新问题与当前主题核心概念链关联弱（并行关系，如 springmvc vs flux）→ 由问题优化智能体（模式A）判断并给出新 `slug`/`title`，**经用户确认**后开新主题文件。
- FR-15：**交叉引用（内链）**——本主题内的新概念用 `[[概念名]]`，涉及他主题概念时用 `[[slug#概念]]`（**正向**）。v1 只做**轻量渲染**（渲染成高亮标签，**不可点击跳转**）；反向引用、点击跳转/知识图谱留 v2。

### 6.6 记忆
- FR-16：记忆记录概念掌握度（四级，见 §7）与用户背景。
- FR-17：**掌握度规则（详见 §7）**——分数制：概念被标注（= 此处不懂）→ **分数不变**（**不在库**则新建 `score = 10`），置 `pending`；用户点「已理解」（**仅 `pending` 时生效、幂等**）→ `pending` 清除、`score = min(100, score + 10)`；`score ≥ 80` 记 `mastered`。**概念分数只读、不可手动修改**（仅背景可手改）。
- FR-18：**背景**——每次会话开始时（**会话=前端页面加载/刷新**）由 AI **独立调用一次**，依据用户知识记忆**与已有主题（只取标题、不加载笔记正文）**推断：**`score ≥ 50` 的概念** → "熟悉 某领域"（如多个 Java 概念达 `familiar`/`mastered` → "熟悉 Java 后端"）；**`score < 50` 的概念**（多为被标注、尚未学会）→ "正在学 某领域"；**长会话中途不重算**；用户可在设置页查看、**手动刷新**或**手动纠正**（手改后锁定）；初始为空串。（注：概念靠标注累积，**首次启动时 concepts 为空 → 背景为空串**，v1 接受，见 Plan §12）

### 6.7 输出规范

各智能体的输出契约（完整 Prompt 见 Plan §6）：

| 智能体 / 模式 | 输出 |
|---|---|
| 解答笔记（模式①作答） | **纯 Markdown 流式**，无结构化字段 |
| 解答笔记（模式②标注扩写） | JSON：`{ "insert": {"insert_text"}, "new_section": {"title","content"}? }`（`new_section` 仅"深入了解"时存在） |
| 问题优化（模式A） | JSON：`{ "optimized_question", "slug", "title" }` |
| 问题优化（模式B） | JSON：`{ "questions": [ {"text","concept","kind","reason"} ] }`（`kind`∈`concept`/`statement`） |
| 背景推断（会话级一次） | JSON：`{ "background": "背景描述（可为空串）" }` |

## 7. 数据模型

> 单用户，SQLite。**v2 多用户扩展方式**：给各表加 `user_id` 列，并在查询/写入时带上 user 条件（v1 不预置该列）。

**掌握度：分数制（0–100）**

| 等级（展示） | 分值区间 | 含义 |
|---|---|---|
| `unfamiliar` | < 20 | 不懂，被用户标注（**被标注新概念默认 10**） |
| `blurry` | 20–49 | 讲过、记不牢 |
| `familiar` | 50–79 | 能理解，经提示可复述 |
| `mastered` | ≥ 80 | 能主动运用 |

**每个概念记录**：`score`（0–100）、`pending`（已被标注、等待「已理解」确认；**兼作「已理解」的幂等依据**）。

**规则（v1，程序计算）**：

1. **概念入库**：概念名来自**问题优化智能体（模式B）**给出的 `concept`；后端做**精确名匹配**——同名 → **复用该记录**（分数按规则2 处理，标注本身不改分）；新名 → 新建记录。同义/层级合并（如"低耦合"与"耦合"）留待后续积累后批量清理。
2. **被标注**（用户明确标注此处理解有困难）：概念**分数不变**；**不在库** → 新建 `score = 10`（`unfamiliar`）；两种情况**均置 `pending = True`**；**同一概念被多次标注仍只置一次 `pending`，只需一次「已理解」即清、+10（不按标注次数叠加）**。`kind=concept` 与 `kind=statement` 同规则（"说法"由模式B 提炼出的概念同样走这条）。
3. **学懂确认**：用户读完扩写内容、点「已理解」→ **仅当该概念 `pending = True` 时**置 `pending = False`、`score = min(100, score + 10)`；`pending = False` 时重复确认**不再加分**（**幂等**，防重复点击/重发导致虚增）。
4. **`mastered` 判定**：`score ≥ 80`。
5. **概念分数只读**：仅由上述规则计算，**不可手动修改**（背景可手改，见规则6）。
6. **背景推断**：**每次会话开始时独立调用一次**——**`score ≥ 50` 的概念**推断用户**熟悉**的领域（如多个 Java 概念达 `familiar`/`mastered` → "熟悉 Java 后端"）；**`score < 50` 的概念**（多为被标注、尚未学会）推断**正在学习**的领域（如大量 Docker 概念被标注 → "正在学 Docker"）；用户可查看并手动纠正，**手改后锁定、不再被自动推断覆盖**。
7. **衰减**（v2）：随时间遗忘降级。

> 不做 LLM 概念自动提取：概念与掌握度**只由用户显式行为驱动**（标注 = 未懂；「已理解」= 已学会），不做"未标注即已懂"的推断。

**表**（DDL 见 Plan §3）：

- `concepts`：概念名、**分数**、`pending` 标记、更新时间。
- `user_profile`：用户背景描述（初始空串）+ 是否被用户手改锁定。
- `notes`：主题名、slug、MD 文件路径、创建/更新时间。
- `questions` / `annotations`：问题与标注记录。

## 8. API

完整接口契约见 **Plan §4**（单一真相源）。概览：

- `POST /api/optimize/initial`：问题优化 模式A（优化问题 + 命名主题）。
- `POST /api/optimize/annotation`：问题优化 模式B（标注 → 候选问题）。
- `POST /api/answer`：**SSE 流式**返回回答纯 Markdown。
- `POST /api/annotate`：处理一个标注（含深度），原地扩写笔记。
- `POST /api/memory/confirm`：对一个已标注概念确认「已理解」（清 `pending`、分数 +10）。
- `GET /api/note/{slug}`：获取笔记内容。
- `GET /api/memory`：读用户知识记忆。
- `POST /api/memory`：纠正**用户背景**（概念分数只读、不可改）。
- `POST /api/memory/refresh`：会话级刷新背景推断（读记忆 → AI 推断 → 写回）。
- `GET /api/notes`：主题列表。

## 9. 技术选型

| 项 | 选择 | 说明 |
|---|---|---|
| 后端 | Python + **FastAPI**（Uvicorn） | 已用 uv 管理，Python 3.13；流式用 `StreamingResponse` (SSE) |
| LLM | **DeepSeek**（可调换） | 通过抽象 LLM 层配置注入模型名 |
| 模型 | **统一使用 flash 级（deepseek-flash）** | 快、便宜、质量足够；模型名写入配置，不写死代码 |
| 前端 | **Vite + React + TypeScript + zustand** | 笔记区（流式回答 + 划词标注）+ 提问/问题确认区 + 设置页 |
| 存储 | **SQLite** | 开发者不熟，SDD 阶段逐步学习 |
| 笔记文件 | `data/notes/{slug}.md`，slug 由 AI 生成、**用户不可改** | 扁平结构，便于跨主题 `[[slug]]` 引用 |
| 多用户 | 单用户 | v2 扩展：各表加 `user_id` 列 + 读写带 user 条件（v1 不预置列） |

### 9.1 LLM 抽象层（关键设计）

模型**不固定死**：封装统一 LLM 调用接口（`chat` / `chat_stream`）。**当前所有调用统一使用同一模型**（flash 级），模型名从配置读取；抽象层保留"按智能体分别配置"的能力，换模型只改配置、不改业务代码。

## 10. 关键设计决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| 回答与笔记关系 | **回答即笔记**，后续提问追加、标注对笔记原地扩写 | 避免"回答一份、笔记一份"的二次改写与冗余 |
| 笔记结构 | **Q/A 分块**：`# {title}` + 若干 `## {问题}` + 回答正文 | 问题与答案组织在一起，便于追溯与阅读 |
| 笔记修改方式 | **优先词后、兜底段末**的标注插入：grep 命中源码 → 插到划词之后；否则逐段脱标记定位段落 → 插段末 | 词后贴合直觉；兜底段末避开字符级定位失败，稳且可单测 |
| 了解深度 | 每个标注单独选「简单/深入」 | 不同概念所需深度不同 |
| 简单 vs 深入 | 简单=括号简释（插在插入点）；深入=括号+紧跟段落新增小标题展开 | 匹配用户当下的理解意愿 |
| 猜问题环节 | **保留**（模式B 生成候选问题，用户确认） | 用户对"问什么"有掌控感，是产品核心体验 |
| 概念记忆来源 | **用户标注（模式B 的 `concept`）+ 「已理解」确认** | 免 LLM 提取，信号确定、可单测；不臆断"未标注即已懂" |
| 记忆喂给 AI | 按 `score` 分【已掌握】(≥50) / 【尚不熟悉】(<50) 两类喂给回答与优化智能体 | 记忆改由标注驱动后，`<50` 多为用户不懂的词，不能当作已掌握，否则污染回答 |
| 标注定位 | 纯手动划词 | v1 简化，先验证核心循环 |
| 记忆粒度 | 概念掌握度 + 背景 | 简单可控、长测易积累 |
| 掌握度默认 | 被标注新概念 10 分（`unfamiliar`） | 标注=“这里不懂”，从低级起步 |
| 掌握度模型 | **分数制 0–100**：被标注**不改分**（新概念入库 10）；「已理解」+10（上限 100） | 显式行为驱动，简单可单测 |
| 学懂判定 | 用户读完扩写后点「已理解」= 一次完成 | 主观确认才是“学会”的强证据，无需 LLM 判定 |
| 标注跳过 | 点「跳过」= 不改记忆、直接进入下一条 | 串行队列需要出路防卡死；跳过 ≠ 撤销（不回滚已写入的扩写） |
| 掌握度权威源 | 程序规则计算（AI 只给概念名） | 规则确定、可单测 |
| 背景维护 | **每次会话独立推断一次** + 用户手动纠正（手改后锁定） | 低频、不拖累每轮流程；锁定防手改被覆盖 |
| 流式方案 | 真流式（SSE）+ 纯 Markdown（无分隔符协议） | 协议简单可靠，无解析脆弱性 |
| 主题边界 | 关联弱（并行关系）则开新主题 + 跨主题**正向**内链 | 匹配并行关系（springmvc vs flux） |
| 自由提问 | 追加进当前主题笔记；关联弱（并行关系）则开新主题 | 统一走模式A，slug 不再依赖前端猜测 |
| 交叉引用（内链） | v1 只做正向 `[[slug#概念]]`/`[[概念名]]`，且**轻量渲染为高亮标签**（不跳转）；反向与跳转 v2 | 避免跨文件写入；渲染属展示层，后做 |
| 深入章节位置 | 紧跟锚点所在段落之后；标题固定 `####`（正文小节最高 `###`） | 与原语境连续，且不与正文小节撞层 |
| 标注时机 | 流式结束、MD 渲染完成后启用 | 避免流式文字位移导致标注错位 |
| 前端选型 | Vite + React + TS + zustand | 类型安全 + 轻量状态管理 |
| 笔记存储 | `data/notes/{slug}.md` | 扁平、易跨主题引用 |
